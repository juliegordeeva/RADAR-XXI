Суммарный размер исключаемых путей — около 80 MiB. Сумма размеров отслеживаемых файлов уменьшается примерно с 180 до 100 MiB. Это не размер пакета push: Git хранит одинаковые копии как один объект и сжимает данные, поэтому выигрыш при передаче меньше.

## Первый push ветки

Удаление отдельным следующим коммитом не уберёт большие файлы из истории первого push. Сейчас поверх `origin/master` находятся коммит редизайна и созданный пользователем коммит `remove extra files`. Чтобы уменьшить первый push, их нужно собрать в один коммит с итоговым очищенным набором файлов. Коммит `master` при этом не меняется.

После проверки подготовленных изменений пользователь может выполнить:

```sh
git branch backup/redesign-before-cleanup HEAD
git reset --soft origin/master
git commit -m "Website redesign based on brandbook, cleaned assets"
git push -u origin redesign/brandbook-v2
```

`reset --soft` меняет указатель только текущей ветки и сохраняет индекс и файлы; следующий commit объединяет изменения двух коммитов и подготовленную очистку. Это переписывает историю текущей ветки. Резервная ветка сохраняет оба старых коммита; её не нужно отправлять через `push --all`. Перед её использованием убедитесь, что ветка ещё не опубликована и не передана коллегам. Если ветка уже появилась на сервере, переписывание следует согласовать отдельно. Сам агент коммит не переписывал и ветку не отправлял.

Очистка сокращает размер передачи, но не доказывает и не устраняет автоматически причину HTTP 400.
